# ปุ่มเปิดระบบ (Start-DEP-PM.exe)

ดับเบิลคลิกครั้งเดียวแล้วใช้งานระบบได้ — แทนการเปิด 2 เทอร์มินัลแล้วพิมพ์ 6 บรรทัด

## ใช้ยังไง

ดับเบิลคลิก **"เปิดระบบ DEP-PM"** บนหน้า Desktop (หรือ `Start-DEP-PM.exe` ที่รากรีโปโดยตรง) มันจะ:

1. ตรวจว่ามี venv ของ backend · สร้าง `.env` / `.env.local` ให้ถ้ายังไม่มี (ลอกจากไฟล์ตัวอย่าง)
2. เตือนถ้า `API_TOKEN` ไม่ตรงกับ `NEXT_PUBLIC_API_TOKEN` (อาการเวลาไม่ตรง = หน้าเว็บขึ้น
   "โหลดบอร์ดไม่ได้" ทั้งที่ backend ปกติ — เคยหลงไปไล่ผิดที่มาแล้ว)
3. อัปเกรดฐานข้อมูลถ้าโค้ดใหม่กว่า schema — **สำรอง `dep_pm.db` ไว้ก่อนเสมอ** (WORKING_RULES Rule 3)
4. สตาร์ต backend `:8500` + หน้าเว็บ `:3000` แล้วเปิดเบราว์เซอร์ให้

จบแล้วค้างเมนูไว้: **[O]** เปิดหน้าเว็บอีกครั้ง · **[S]** หยุดระบบ · **[Q]** ออกโดยปล่อยให้รันต่อ

> ปิดหน้าต่างเฉย ๆ ระบบ**ยังรันอยู่** (ตั้งใจ — จะได้ปิดหน้าต่างทิ้งแล้วทำงานต่อได้)
> เปิด exe ใหม่แล้วกด **[S]** เพื่อหยุด (หยุดของรอบก่อนได้ด้วย ไม่ใช่เฉพาะที่ตัวเองสตาร์ต)

## สิ่งที่มันไม่ทำ (ตั้งใจ)

- **ไม่แตะพอร์ต 8000 (d_CEO) และ 8400 (d_Jarvis)** — ของระบบอื่นที่รันค้างตลอด · แสดงสถานะให้ดูเฉย ๆ
- **ไม่สตาร์ตซ้อน** — ถ้าพอร์ตมีคนใช้อยู่แล้วและตอบ `/health` แบบ DEP-PM จะใช้ตัวเดิม
  (เคยเกิดจริง: uvicorn 2 ตัวบนพอร์ตเดียว ตัวที่ถือพอร์ตเป็นคนละตัวกับที่คิด)
- **ไม่สร้าง venv / ไม่ลง dependency ของ backend ให้** — งานติดตั้งครั้งแรกต้องมีคนดู
  (มันจะบอกคำสั่งที่ต้องพิมพ์ให้ ถ้ายังไม่มี)
- **ไม่แก้ `.env` ที่มีอยู่แล้ว** และไม่พิมพ์ค่าคีย์ออกจอ · ไม่ commit / ไม่ push / ไม่ลบอะไร

## Build ใหม่ (เมื่อแก้ `dep_pm_launcher.py`)

```powershell
backend\.venv\Scripts\pip install -r tools\launcher\requirements-build.txt   # ครั้งเดียว
.\tools\launcher\build.ps1
```

ได้ `Start-DEP-PM.exe` (~8.5 MB) ที่รากของรีโป — **gitignored** เพราะเป็นผลลัพธ์ที่ build เอาเองได้

## ชอร์ตคัตบนหน้า Desktop

```powershell
.\tools\launcher\make-shortcut.ps1
```

สร้าง/เขียนทับชอร์ตคัตชื่อ **"เปิดระบบ DEP-PM"** บนหน้า Desktop ของผู้ใช้ปัจจุบัน
· รันซ้ำได้เมื่อ build ตัว exe ใหม่หรือย้ายโฟลเดอร์รีโป

> ชื่อและคำอธิบาย (ภาษาไทย) อยู่ในไฟล์ `shortcut-name.txt` — บรรทัดแรก = ชื่อ · บรรทัดสอง = คำอธิบาย
> · แยกออกมาเพราะสคริปต์ `.ps1` ต้องเป็น ASCII (ดูหัวข้อล่างสุด) แต่ชอร์ตคัตควรเป็นภาษาไทย
> ให้เข้าชุดกับตัวอื่นบนหน้าจอ · อยากเปลี่ยนชื่อ = แก้ไฟล์นั้นแล้วรันสคริปต์ใหม่

## ข้อจำกัดที่ต้องรู้

- **ไม่ได้ฝัง Python/Node** — เป็นปุ่มกดที่เรียกของที่ติดตั้งบนเครื่องนี้อยู่แล้ว
  ⇒ ต้องวางไว้**ในโฟลเดอร์รีโป** (มันหาโฟลเดอร์ระบบจากตำแหน่งตัวเอง) และย้ายไปเครื่องอื่นเปล่า ๆ ไม่ได้
- หน้าเว็บสตาร์ตด้วย `npm run dev` (โหมดพัฒนา ตามที่ runbook §1 ใช้) ไม่ใช่ production build
- log ของทั้งสองตัวอยู่ที่ `logs\backend.log` และ `logs\frontend.log` (gitignored)
- Windows เท่านั้น (ใช้ `taskkill`/`netstat` ในการหยุดต้นไม้ของกระบวนการ)

## ทำไม `build.ps1` เป็นภาษาอังกฤษล้วน

Windows PowerShell 5.1 อ่านไฟล์ `.ps1` เป็น ANSI ถ้าไม่มี BOM แต่กติกาบ้านนี้คือ **UTF-8 ไม่มี BOM**
(WORKING_RULES §6.1ข) — เขียนไทยลงไปแล้ว parser พังทันที (เจอจริงตอนสร้างไฟล์นี้)
⇒ ข้อความในสคริปต์ build เป็น ASCII ล้วน ส่วนตัวโปรแกรม (`.py`) ใช้ไทยได้ตามปกติ
