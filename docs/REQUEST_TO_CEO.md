## 1. เราเป็นใคร และต่อกับคุณตรงไหน

DEP-PM Platform คือ **ทีม R&D** ปลายสาย `Vinit → d_Jarvis → d_CEO → DEP-PM`
รับ task ที่คุณ `assigned_team_id` = **Research & Development** มาแตกเป็นงานย่อย
ให้ agent ลงมือทำจริง แล้วรายงานผลกลับเข้า **QC gate** ของคุณ

เราเป็น **consumer ฝ่ายเดียว** — เรียก API ของคุณ 3 เส้นเท่านั้น ไม่ขอให้คุณแก้โค้ด:

| ใช้ทำอะไร | endpoint ของคุณ |
|---|---|
| หา `team_id` ของ R&D จากชื่อ (ไม่ hardcode id) | `GET /teams` |
| ดูงานที่รออยู่ | `GET /tasks?status=queued` |
| แจ้งรับงาน / ส่งผลงานกลับ | `PATCH /tasks/{id}` |

**ข้อผูกมัดฝั่งเรา:** ส่งกลับได้แค่ `in_progress` และ `qc_review` เท่านั้น —
`done`/`awaiting_approval`/`rejected` ถูกบล็อกด้วย guardrail ในโค้ด (ValueError ก่อนยิง HTTP)
**เราปิดงานเองไม่ได้ ทุกงานต้องผ่าน QC ของคุณ** (มติ Vinit 2026-08-02)

## 3. สิ่งที่ขอ

### 3.1 ยืนยัน contract + ออกเอกสารฝั่งคุณ

ปัจจุบัน **d_CEO ยังไม่มีเอกสารใดกล่าวถึง DEP-PM เลย** ขอให้ออก `docs/INTEGRATION_DEPPM.md`
ตามแบบเดียวกับ `INTEGRATION_JARVIS.md` / `INTEGRATION_MOS.md` ที่คุณมีอยู่แล้ว
· ฝั่งเราเขียนไว้ครบแล้วที่ `docs/INTEGRATION_CEO.md` (เปิดอ่านได้เลย ใช้เป็นร่างได้)

### 3.2 แก้เอกสารที่ล้าสมัย 🔴

`project_plan_solo_ceo.md` §9.1 ยังเขียนว่า *"d_DEP-PM ควบรวมเป็น engine เดียวกับ Solo_CEO"*
— **ขัดกับสายบังคับบัญชาที่ Vinit ยืนยันเมื่อ 2026-08-02** และขัดกับสิ่งที่เพิ่งเกิดขึ้นจริง
(งานของคุณถูกทำเสร็จและผ่าน QC โดยระบบที่แยกกันอยู่)

เหตุผลที่ไม่ควรยุบรวม: orchestrator ของ d_CEO เรียก LLM **แบบไม่มี tool** → ได้ข้อความล้วน
ส่วน DEP-PM มี state machine, bus, deploy pipeline และ agent ที่ทำงานเป็นขั้นตอนพร้อม
audit trail ครบ — คนละบทบาทกัน ไม่ซ้ำซ้อน

> `d_Jarvis\docs\VISION.md` §5 มีข้อความทำนองเดียวกัน — ฝากแจ้ง session ของ Jarvis ด้วย
> (เราไม่แก้ข้ามรีโปเช่นกัน)

### 3.3 ยืนยันกติกาการมอบงาน

งานที่ต้องการให้ทีม R&D ทำ **ต้องตั้ง `assigned_team_id` = ทีม Research & Development
ตอน `POST /tasks`** ไม่งั้นเราไม่เห็นในคิว (เราไม่ดูดงานที่ไม่ระบุทีม โดยเจตนา)

### 3.4 แจ้งล่วงหน้าถ้าจะเปลี่ยน API

ถ้า 3 endpoint ข้างบนจะเปลี่ยน request/response หรือชื่อสถานะ รบกวนแจ้งก่อน —
ฝั่งเรารวมการยิง HTTP ไว้ในไฟล์เดียว (`integrations/ceo_client.py`) แก้ตามได้เร็ว

### 3.5 (ทางเลือก) ถ้าอยากให้รับงานอัตโนมัติ

ตอนนี้ **ผู้ใช้กดรับงานเอง** ตามหลัก "ยืนยันก่อนทำ" ของ ecosystem
ถ้าต้องการให้อัตโนมัติ เลือกได้ 2 ทาง — เราทำได้ทั้งคู่โดยไม่ต้องแก้ contract:
- เรา poll คิวของคุณตามความถี่ที่ตกลง หรือ
- คุณยิง webhook มาที่ DEP-PM (`http://127.0.0.1:8500`) ตอนมีงานของทีม R&D เข้าคิว

## 4. ของฝากจากผลตรวจ QC รอบล่าสุด (เราเห็นด้วยและกำลังแก้)

QC ของคุณจับได้ว่า agent เราเขียนงานโดย **กุหลักฐานขึ้นมาเอง** (อ้างชื่อคน, quote, timestamp,
screenshot ที่ไม่มีอยู่จริง) — รอบนั้นไม่หลุดถึง deliverable แต่เรารับไว้เป็นงานลำดับแรก
กำลังเติมกติกาห้ามกุหลักฐานลงใน persona prompt ของทุกบทบาท

**ข้อเสนอ SOP ของคุณ** ("ผลงานที่ส่ง QC ต้องแนบตัวชิ้นงานจริง ไม่ใช่รายงานสรุปสถานะ task")
เราทำตามแล้วตั้งแต่ 2026-08-03 — เห็นด้วยว่าควรเป็นกติกากลางของทุกทีม
